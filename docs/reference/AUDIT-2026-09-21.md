# Code audit and fixes — 2026-09-21

## Scope and confidence

This is a source review and regression-testing pass, not a certification that every
line, paid module, adapter runtime or deployment is vulnerability-free. Review
focused on authorization, storage mutations, multipart upload, metadata import,
URL import, token verification and iframe messaging. No deployment, commit,
release, production-data mutation or secret inspection was performed.

## Fixed findings

| Area | Finding and fix |
| --- | --- |
| Multipart upload | Post-completion policy checks could destroy the previous object. Validate selected S3 parts/ETags and real size before completion; enforce collision, owner, quota and file-count policies in standalone/Laravel/WordPress; conditional completion protects non-overwrite destinations. |
| Original-content API | `allow_download=false` did not block `getContent`; now returns 403. |
| Editor writes | Enforce storage-quota delta before writing; refresh metadata size and content hash so stale dedupe cannot discard a subsequent upload. |
| File counts | Enforce destination count for cross-disk copy/move and preflight new ZIP extraction targets. |
| DB metadata | Import checks modification rights and forces the authenticated owner for owner-only tokens. Owner-only rows without titles remain visible to authorization. Pass the DB connection into standalone route dispatch so DB import/export can execute. |
| URL import | Pin each hop to previously validated IPs via cURL resolution; disable proxy inheritance on this fetch path to avoid bypassing address validation. |
| Browser wrappers | SDK/React/Vue require messages to originate from their own iframe window, not merely the same origin. |
| Node verification | Validate numeric time claims, exact expiry boundary and future `nbf`/`iat` consistently with the PHP verifier. |
| Documentation | Correct ZIP atomicity claims: structural preflight is not transactional rollback for per-entry scan/write failures. |

## Validation performed

- PHP unit/integration, adapter smoke and license-server checks in disposable PHP
  8.3 containers: 79 non-skipped test files passed, including the separately rerun
  deploy-lock suite with Bash installed. This is a suite/file count, not assertion count.
- New core policy regressions: 15 integration cases and 4 multipart mocked-S3 cases.
- HTTP tests: image 16, stream 8, usage 4, virus 6, ZIP 6 and new write-policy 4 cases passed.
- JS: Node 39, SDK 11, React 10, Vue 11 tests passed; Node/React/Vue type checks passed.
- Locale parity: all 16 locales passed. Three Node-to-PHP interop cases skipped
  because host PHP dependencies were unavailable.
- Full PHP execution used the existing container dependencies; host core/vendor
  was unavailable. Container tests copied current source into the disposable image,
  leaving host storage untouched. Displayed PHP warnings were routed to stderr.

## Remaining verification and limitations

- Live S3/R2/MinIO multipart behavior, MySQL/PostgreSQL, live SFTP/SSH, full Laravel
  DB integration, browser/editor E2E, Python SDK and publish/build pipelines were
  not validated in this pass. Updated live-S3 regression source is not a live-provider result.
- Quota/count checks remain check-then-write, not atomic reservations across
  concurrent writers. This patch does not prove strict limits under concurrency.
- Image transformations, restores and module-generated writes need a separate
  exhaustive policy/concurrency pass; do not infer coverage from editor/upload tests.
- ZIP extraction can leave earlier entries written if a later scan/write fails.
  Legal-hold in-place write semantics remain the existing v1 design.
- Source-level adapter smoke tests do not replace real WordPress/Laravel execution.

## Release and operational requirements

- Laravel/WordPress now require core `^0.2.88` because they call the new shared
  multipart validator. This is a coordinated-release requirement; this audit does
  not publish core 0.2.88 or change package release versions.
- Grant `s3:ListMultipartUploadParts`; verify conditional multipart completion on
  each S3-compatible provider. See CONFIG.md for lifecycle cleanup guidance.
- Source SDK/wrapper changes require normal package builds before publishing;
  generated `dist/` and vendored dependencies were not edited.
