# FluxFiles AI Context

This directory is for AI agents working on the FluxFiles codebase. Read this file first, then use the linked notes for deeper context. The repo root [`AGENTS.md`](../AGENTS.md) is the tool-agnostic summary of the same guidance — keep the two roughly in sync.

## Product Summary

FluxFiles is a standalone, embeddable PHP file manager (PHP ≥ 8.2.35). The core app exposes a PHP API and zero-build frontend that can be embedded by iframe/SDK. The repo also ships adapters for Laravel, WordPress, React, Vue/Nuxt, CKEditor 4, TinyMCE, and Summernote, token SDKs for Node and Python, and an MCP server.

Primary capabilities:

- Local, AWS S3, Cloudflare R2 and SFTP storage through Flysystem v3.
- JWT auth with permission, disk, path prefix, upload size, extension, quota, owner-only, and BYOB disk claims.
- File operations: list, upload (plain, resumable tus, S3 multipart, presigned PUT/POST), download presign, rename, move, copy, delete/trash, mkdir, cross-disk copy/move, import-from-URL, zip/extract.
- Metadata: title, alt text, caption, tags, file hash, ownership, search index, folder index, HMAC-chained audit log.
- Image processing: WebP variants, on-demand WebP/AVIF, crop, watermark, optional `strip_exif`, opt-in PDF/video posters.
- Optional AI tagging through Claude/OpenAI-compatible vision providers.
- Iframe SDK and framework wrappers that communicate by `postMessage`.

## Working Rules

- Do not treat the server as the owner of user metadata. Metadata should live with user storage, not in a central database. **Exception:** the opt-in `FLUXFILES_STORAGE_BACKEND=db` mode (env var, default `json`) moves that bookkeeping — metadata, search/folder index, audit log, trash manifest, quota, and the rate limiter — into the operator's own self-hosted MySQL/PostgreSQL/SQLite instead of JSON files. File bytes stay fully storage-resident either way; it's not a JWT claim and not a paid module. See `docs/design/DB-STORAGE-MIGRATION-DESIGN.md`.
- Keep JWT enforcement centralized and consistent: disk access, permissions, path scope, owner-only, upload size, and extension checks matter.
- Never expose storage credentials. BYOB credentials are encrypted in JWTs and decrypted only at runtime.
- Do not add new stateful server dependencies unless the task explicitly changes the stateless/BYOB direction.
- Avoid editing `dist/` files unless the task is specifically about published artifacts. Prefer source under `src/` and rebuild.
- Do not read or print secrets from `.env` unless the user explicitly asks. Use `.env.example` for documentation.
- `packages/core/storage/`, metadata sidecars, `_fluxfiles/`, generated variants, lock/index files, `storage/tus/` staging, and uploaded test files are runtime data.
- **Config = JWT claims; `docs/reference/CONFIG.md` is the single source of truth** (every claim + env var). When you add/rename a claim you MUST document it there — `tests/unit/test-config-doc.php` fails CI otherwise. Mint claims with the **one-options-array** API: `fluxfiles_token(['user'=>…, 'claims'=>[…]])`; the `claims` map (also in node/python/laravel/wordpress) is the escape hatch for any claim by its raw name. The legacy positional signature still works but isn't the documented form.
- **Never put the main JWT in a URL.** Adapters send it via `postMessage`; API calls use `Authorization: Bearer`. The standalone `?token=` is **dev-only** — it's stripped on boot (`history.replaceState`) and `/public/index.html` sends `Referrer-Policy: no-referrer`. Per-file `/img` & `/stream` query-string tokens are fine (scoped to one file + short TTL + distinct token type). CSRF is checked via the `Origin` header (not `Referer`), so `no-referrer` is safe.
- **External tools never inherit the environment.** Anything started with `proc_open` (gs, ffmpeg, ssh, tesseract, c2patool, clamdscan) gets `ProcessEnv::minimal()` (PATH/HOME/TMPDIR/LANG only) — a parser exploited by an upload must not be able to read `FLUXFILES_SECRET` or cloud keys. Keep it that way for any new tool.
- **BYO-embed over build-and-sell.** Where excellent free OSS self-host exists, embed it via a free config toggle instead of building/selling a competitor. **All four are shipped** (each a free http(s)-validated claim that makes the UI iframe the operator's own instance): terminal → `terminal_pty_url` (ttyd/gotty/wetty), PDF → `pdf_tools_url` (Stirling-PDF), office → `office_url` (Collabora/OnlyOffice), e-sign → `esign_url` (DocuSeal). `office_url`/`esign_url` may carry a `{url}` placeholder the UI substitutes with the selected file's URL. Genuine paid value only where there's no OSS drop-in AND it fits the stateless/storage-resident grain.
- **Release** = per-package tags (`core-vX.Y.Z`, `react-vX.Y.Z`, `node-vX.Y.Z`, `mcp-vX.Y.Z`, …). Bump `package.json` for changed JS packages (react/vue/sdk/node/mcp); core & PHP adapters are versioned by the tag. **Push ≤3 release tags per `git push`** (>3 silently skips publish workflows) — batch them. Add a `CHANGELOG.md` entry. **Its internal `0.2.X`/`0.3.X` is its OWN counter and does NOT equal the core tag** — the two drifted apart once adapter-only releases started getting their own entries (e.g. `[0.2.72]` → `core-v0.2.63`, and `[0.3.26]` → `core-v0.2.100`). Always read `git tag | grep '^core-v' | sort -V | tail -1` for the real next core version; never derive it from the changelog. Each entry carries a `> Released:` line naming the exact tags. This bit a private module once: its `composer.json` floor was set from the changelog number to `^0.2.78`, a version core will not reach for years.
- **PHP floor is `^8.2.35`** (8.1 is EOL; CI matrix 8.2–8.4). Five places must agree: every `composer.json` `require.php` + `config.platform.php`, the WP plugin header/`readme.txt` `Requires PHP`, `FLUXFILES_MIN_PHP` and `FluxFilesUpdater::REQUIRES_PHP` (the WP release catalogue carries `requires_php`); `test-wp-smoke.php` guards the WP side.
- **Paid-module releases** are their own repos (`v1.0.0`, not `core-v…`), so the ≤3-tags rule does not apply. Two rules that do: (1) a module's core floor must be the first core release whose `index.php` **calls** that module — composer answers "which core may this install against", and core is the caller, so a lower floor permits an install that is present, licensed and never invoked (this shipped for `virus`); it can't be CI-guarded because the packages are gitignored, so check it by hand. (2) A tag is not a release — `php scripts/pack-modules.php` builds the zips + `build/modules/catalogue.json` that `docs/update-server.example.php` serves and `UpdateClient` re-hashes. It builds from the **tag** (never the worktree), refuses a non-reproducible build, and rejects a layout `UpdateClient::install()` would mis-extract.

## Current Notes

- Delete: `/delete` is permanent (used by purge/API). Files **and folders** have **soft-delete** via `/trash` (+ `/trash/restore|list|purge|empty`) — move-based into `_fluxfiles/trash/<id>/` with a `_fluxfiles/trash.json` manifest (storage-resident, scoped by prefix/owner; folders move the whole subtree incl. variants). The UI soft-deletes everything to trash.
- `docs/ROADMAP.md` (gitignored, local) is the current roadmap/business-strategy doc, cross-referenced against the codebase; `docs/COMMERCIAL-STRATEGY.md` + `docs/LICENSING-PLAN.md` (both gitignored too) cover the paid-tier model. Verify implementation before following any roadmap endpoint.
- `docs/reference/METADATA-STORAGE-DESIGN.md` captures the important principle that metadata travels with user storage. `docs/design/DB-STORAGE-MIGRATION-DESIGN.md` is the deliberate, opt-in reversal of that for operators who want the bookkeeping in their own relational DB instead — see the Working Rules exception above.
- Auth uses `firebase/php-jwt` **v7** (constraint `^7.0`): HS256 keys must be **≥ 32 bytes** or token encode/decode throws. `JwtCompat`/`ImageCompat` shims abstract jwt v5–v7 / intervention v2–v3.
- Local metadata sidecars live at `_fluxfiles/meta/{key}.json` (not `{file}.meta.json`), so a user-uploaded `*.meta.json` cannot collide with or overwrite them. S3/R2 use object metadata.
- `owner_only` is also enforced at folder level (delete/rename/move a folder containing other users' files → 403 via `assertOwnsTree`). BYOB endpoints are SSRF-checked.
- **URL import** (`POST /api/fm/import-url`, `UrlImporter.php`): synchronous server-side fetch → the upload pipeline. Opt-in per tenant via `allow_url_import` (default false → inert). `SsrfGuard.php` is the shared SSRF denylist (per-hop + post-connect IP check; also used by the BYOB endpoint check). v1 is sync (no Redis/queue — by design); a storage-resident job model would be the v2 path if async is ever needed.
- **Resumable uploads (tus 1.0)** (`POST/HEAD/PATCH/DELETE /api/fm/tus`, `TusServer.php`, free/core): lifts PHP's `upload_max_filesize` ceiling on local/SFTP disks and resumes after a dropped connection. Every upload rule (perm, disk, ext, `max_upload`, scope, quota, `max_files`, collision, `owner_only`, legal hold) is checked at **creation**, before any byte is staged; an upload is bound to the creating token's `sub` + `prefix` + disk. The last chunk runs the normal upload pipeline. Partial bytes live in `<FLUXFILES_STORAGE_PATH>/tus/` (server-local, swept after 24 h — **multi-node needs a shared dir or sticky sessions**). **Core-only — not proxied** by Laravel/WordPress; the UI falls back to a plain upload there. Own bucket `FLUXFILES_TUS_RATE_LIMIT` (600/min).
- **Presigned uploads:** `POST /api/fm/presign` with `method: "PUT"` can't bind the body size (advisory only, 15-min TTL cap); `method: "POST"` returns an S3 form-upload policy the **bucket** enforces (`content-length-range`, exact key, pinned `Content-Type`) — R2 has no POST Object (`400 presign_post_unsupported`). `allow_presign_put: false` refuses PUT. Both are refused while virus/DLP scanning is on.
- **Media preview** (inline `<video>`/`<audio>`/pdf already exists): the UI auto-refreshes an expiring presigned media URL on playback error (re-presign via `/api/fm/presign`, keep `currentTime`). Claims: `media_preview` (default true), `preview_url_ttl` (media files get a longer presigned TTL), `max_preview_mb` (oversized → download placeholder). **Gated local media** (`FLUXFILES_LOCAL_PRIVATE=true`): local files serve through `/api/fm/stream?token=` (`StreamToken` + `RangeStreamer`, Range-capable, nginx `X-Accel-Redirect` fast path) instead of static URLs, so an `<video>` can't open without a token — the disk root must then not be served statically. `stream_token_ttl` claim.
- **Posters for PDFs/videos** (`MediaPoster.php`, claim `media_posters`) are **opt-in (default `false`)** since core-v0.2.100 — they run Ghostscript/ffmpeg on every uploaded PDF/video. **Ghostscript older than 10.05.0 is treated as not installed** (published `-dSAFER` bypasses), for posters and PDF optimize alike. ffmpeg runs with a forced demuxer and `-protocol_whitelist file`.
- **`strip_exif`** (`ExifStripper.php`, default `false`, forced on in demo mode): lossless container-level removal of EXIF/XMP/IPTC/PNG text from JPEG/PNG/WebP, keeping only Orientation + ICC. For JPEGs it also cuts everything after the main image's EOI (phone MPF secondary images — HDR gain/depth maps with their own GPS — and vendor trailers) and drops the MPF index. Covers `/upload`, `/import-url`, `/tus`, `/extract` entries and Intake portal uploads; never direct-to-bucket uploads.
- **On-demand WebP/AVIF** (`GET /api/fm/img`, `ImageToken` + `ImageOptimizer::transform`): extends the upload-time variants with arbitrary sizes; cache lives in the file's `_variants/` (free invalidation via existing delete/trash cleanup). Width rounded 100px + clamped (`webp_max_width`), quality snaps to 60/75/80/90 → variant count bounded without per-request counting. **`format=auto` (default) content-negotiates AVIF→WebP→original from `Accept`** (AVIF needs intervention v3 + GD `imageavif`; `ImageOptimizer::avifSupported()` gate); avif/webp cache as separate keys (format is in `transformCacheKey`), response sends `Vary: Accept`; `format=avif`/`webp` force it. **Box sizing**: `height` + `fit` (cover crops / contain fits, default) + `dpr` (1/2/3, multiplies the requested size) — all folded into the cache key, never upsize. SVG/animated-GIF/bomb never converted. S3/R2 cache-hit 302-redirects to a presigned URL (no app egress). Image entries get `img_base` in `list()` when `webp_enabled` + a stream secret are set. Claims: `webp_enabled`/`webp_max_width`/`webp_default_quality`. **AVIF delivery is free/core.**
- **Optimization is now FREE/core** (`POST /api/fm/optimize`, `\FluxFiles\OptimizeModule` + `\FluxFiles\PdfOptimizer`, both in `packages/core/api/`): recompress images → WebP at rest (replace/keep, EXIF stripped) + Ghostscript PDF compression + batch + on-upload `auto_optimize` + savings in the usage dashboard (`OptimizeStats`). Opt-in per token via `allow_optimize` (it replaces/deletes originals → `optimize_forbidden` 403 without it); needs `write` (and `delete` to replace the original). It was a paid module but the value was thin once AVIF/WebP delivery became free in `/img`, so it was folded into the MIT core (removed from `ModuleRegistry`; the `optimize_format`/AVIF-at-rest path is gone — WebP-only). The `packages/optimize/` private package is retired. PDF needs `gs` ≥ 10.05.0 on the server → `501 pdf_unavailable` when absent or older.
- **Duplicate finder** (`GET /api/fm/duplicates`, `FileManager::findDuplicates`, free/core): byte-identical files under the token's root, size pre-filter then streamed SHA-256 (≤ 512 MB hashed per call), shares the 2/min usage-refresh bucket; the usage dashboard moves extra copies to trash.
- **SSH terminal** (`POST /api/fm/terminal`, `SshTerminal`, SFTP disks only): stateless **command-runner** (one `exec` per request, cwd threaded back), opt-in `allow_terminal` claim (default off), `write` perm, audited, server kill-switch `FLUXFILES_TERMINAL_DISABLED`. **Proxied by both Laravel and WordPress too** (`FluxFilesController::terminal()` / `FluxFilesApi::handleTerminal()`), gate claim forwards unconditionally in both proxy adapters. **Optional free PTY upgrade:** the `terminal_pty_url` claim (http(s) only, validated in Claims) makes the UI **embed a self-hosted ttyd/gotty/wetty** (the operator runs it on their own box) via iframe for a true interactive terminal (vim/top/htop) instead of the command-runner — empty (default) → command-runner. **Free/core config toggle, never a paid module** (a paid PTY SKU was rejected: browser terminals are commodity OSS). The Go-sidecar idea is dropped in favor of BYO ttyd.
- **One-click Git deploy** (`POST /api/fm/git-deploy`, `GitDeploy.php`, SFTP disks only, free/core): a fixed-command-shape **subset** of the SSH terminal above, not a second arbitrary-shell door — repo path/branch/hooks-enabled are **operator claims** (`git_deploy_path`/`git_deploy_branch`/`git_deploy_hooks`), never accepted from the request body. Dedicated `allow_git_deploy` claim (default off), never bundled with `allow_sftp`/`allow_terminal`. `core.hooksPath` is pinned either way (`/dev/null` by default, the repo's own `.git/hooks` with `git_deploy_hooks`), other config-driven exec is neutered unconditionally, and a pre-deploy **allowlist** audit of `git config --list --show-scope` (local + worktree scopes) refuses a repo with any unexpected key (`409 git_deploy_unsafe_repo`; the earlier denylist was bypassable and was replaced in core-v0.2.92). Writes into any `.git` segment on SFTP disks are refused everywhere. `mkdir`-based lock directory (PID-liveness checked) on the repo itself serializes concurrent deploys. **Proxied by both Laravel and WordPress too** (`FluxFilesController::gitDeploy()` / `FluxFilesApi::handleGitDeploy()`, requires core ≥ 0.2.81) — both proxies reuse the generic write rate-limit bucket instead of core's dedicated `FLUXFILES_GIT_DEPLOY_RATE_LIMIT` bucket, since neither adapter has any per-action bucket precedent (not even `import-url`). See `docs/security/GIT-DEPLOY-SECURITY-REVIEW.md` for the full threat model; non-atomic deploy onto a live webroot is documented, not solved (§4.8).
- **ACL role presets** (`docs/design/ACL-ROLE-PRESETS-DESIGN.md`): a mint-time-only `role` claim-bundle preset — **four roles**, `viewer`/`editor`/`admin`/`superadmin` (`superadmin` shares `admin`'s claim bundle but is the one role documented as safe to combine with an empty `prefix`), structurally parallel to the existing `edition` preset — shipped across all the token builders (`packages/core/embed.php`'s `fluxfiles_role_preset()`/`fluxfiles_apply_role_preset()`, `packages/node/src/token.ts`'s `ROLE_PRESETS`, Laravel's `FluxFilesManager.php`, WordPress's `FluxFilesPlugin.php`, and later the Python SDK) in commit `70f1cea` (2026-09-01). Same-day fix (`d880b98` core/Laravel/WordPress, `fb7c8a2` Node) for a `viewer`/`editor` bug: the presets originally omitted `allow_extract`/`allow_chmod`, assuming an absent claim decodes false, but `Claims::fromJwtPayload` defaults those two specifically to **true** when absent — so a minted `viewer`/`editor` token unintentionally carried `allow_chmod=true`, letting a read-only/contributor role chmod on an SFTP disk. Fixed by setting both explicitly in every builder. No new server-side state and no new JWT claim: `role` only expands to *existing* claims at mint time (never touches `prefix`/`disks`/`userId`/quota/rate-limit/BYO-embed-URL claims, and never implies any paid-module `allow_<x>` claim or `allow_terminal` — terminal access stays an explicit opt-in regardless of role). WordPress maps WP capabilities to roles; `admin` needs `manage_options` or `delete_others_posts` (since wordpress-v0.2.54 — `delete_posts` alone used to mint admin for Contributors/Authors).
- **SFTP host-key / cipher hardening** (`DiskManager::buildSftpProvider()`, config keys `require_host_key`/`strict_algorithms`, env `SFTP_REQUIRE_HOST_KEY`/`SFTP_STRICT_ALGORITHMS`): two opt-in (default-off, backward-compatible) tightenings on top of the pre-existing `host_fingerprint` pinning. `require_host_key` fails closed at disk-build time (`sftp_host_key_required` error) if `host_fingerprint` isn't also set, instead of silently trusting any host key. `strict_algorithms` passes a modern-only `preferredAlgorithms` allowlist (curve25519/ECDH/DH-group16+ KEX, ed25519/ecdsa/rsa-sha2 host keys, AES-GCM/CTR/ChaCha20 ciphers, SHA-2 MACs) to `SftpConnectionProvider`, excluding phpseclib's legacy-compat defaults (SHA-1 KEX, RC4, 3DES, CBC ciphers, ssh-dss, MD5/SHA-1 MACs) — turning it on for a legacy/embedded SFTP server fails the handshake outright rather than downgrading. BYOB SFTP configs get both keys for free since `CredentialEncryptor::validate()` doesn't allowlist config fields.
- Both `/stream` and `/img` mint only when `FileManager::setStreamSecret()` is called — index.php always does, and the Laravel/WordPress **proxy** controllers now do too (unconditionally, in their shared `fileManager()` builder), so both routes are **proxied** by both adapters (ported directly into each controller since `handleMediaStream()`/`handleImageTransform()` are inline functions in `index.php`, not a reusable file — same pattern as the SSH terminal port). They reuse `FLUXFILES_SECRET` for their per-file tokens (`t=stream` / `t=img`, distinct types — one can't be used on the other's endpoint). SFTP-disk streaming rides the same `/api/fm/stream` route, so it's proxied too. The preview-time watermark **overlay** claim (`watermark_enabled`) is still NOT forwarded by either proxy adapter — that's a separate, still-valid restriction: the proxy's `/img` port doesn't implement overlay compositing, so forwarding the claim would mint a token whose watermark gets silently dropped (see `FluxFilesManager.php`'s comment on `watermark_enabled`).
- **Watermark logo + transparent base gotcha:** intervention/image v3's `place()` with opacity<100 composites through an opaque GD scratch image (`imagecopymerge`), so a logo over a **transparent (alpha) PNG/WebP** base comes out a dark box (JPEG is fine — no alpha). Fix = bake opacity into the logo's own alpha then place at 100% (`ImageCompat::bakeLogoOpacity`, used by both `placeLogo` overlay + `placeLogoAt` burn-in). Don't reintroduce opacity-on-`place()`.
- **Modal chrome dark-mode anti-flash:** the React/Vue/SDK modal chrome lives in the HOST origin and can't read the cross-origin iframe's resolved theme, so when the `theme` prop is `auto`/unset it mirrors the embedded UI's boot: resolve dark from `localStorage['fluxfiles_theme']` first, then OS, and persist an explicit theme. Computing chrome `dark` only from `prefers-color-scheme` flashes a light header before a dark theme settles.
- **Paid modules: 13** — `share`, `intake`, `versioning`, `webhooks`, `ai`, `ocr`, `virus`, `backup`, `c2pa`, `audit-export`, `sso`, `dlp`, `legal-hold` (all gitignored private packages, gated by the `ModuleRegistry` 3-layer check). **`ModuleRegistry::$map` is the source of truth — read it rather than trusting a count written down anywhere, including here.** `optimize` was once paid but is now FREE/core, not counted here (see the optimization note above). Strategy: Share + Intake are the sellable heroes (Pro); Versioning + Webhooks are à-la-carte; AI/OCR/terminal/backup are not standalone SKUs (free OSS or BYO-key) — see the gitignored `docs/COMMERCIAL-STRATEGY.md`. `audit-export`/`sso` are the Enterprise Compliance Bundle (later joined by `dlp`/`legal-hold`), built deliberately ahead of a named prospect (an explicit override of `docs/ROADMAP.md`'s default caution against speculative builds).
- **Operator UI for paid modules** — all behind the same `proGate('allow_x', '<module>')` three-state treatment (hidden / locked teaser / on): Share, Intake, Versioning, **AI Vision** (modal for bg_remove/upscale/smart_crop + detail-panel/context-menu/action-sheet entries; `canAiVisionFile()` mirrors `ImageOptimizer::isImage()`'s raster set, no SVG), **OCR** (language picker, copy, "save as caption"), **Virus** ("uploads are scanned" note, per-batch clean-scan toast, on-demand "Scan for viruses" → `POST /api/fm/virus/scan`), **Backup** (folder → another of the token's disks, copied/skipped/errors summary), **Audit export** (inside the Activity panel, plus "Integrity check" → `/fixity/check` and "Verify log" → `/audit/verify`), **Legal hold** (place/release, plus "Retention" → `/retention/run` when the token carries `retention_rules`). C2PA, Webhooks and DLP remain engine-only (API/config, no UI); SSO adds only the "Sign in with SSO" button.
- **Audit log is archive-before-truncate and tamper-evident; export/verify/purge/fixity are a separate paid layer.** `StorageMetadataHandler::audit()`'s rotation writes the dropped tail to `_fluxfiles/audit/archive/audit-<ts>-<hex>.jsonl` first, under the same lock — a free/core correctness fix. Every entry is HMAC-chained to the previous one (`AuditChain`, key = HKDF of `FLUXFILES_SECRET`) on every backend (JSON, core/Laravel/WordPress DB handlers with an `audit_chain_head` row lock). `readAuditArchive()`/`purgeAuditBefore()` are the storage primitives (no Claims/license awareness); `GET /api/fm/audit/export` (NDJSON/CSV, full unpaginated dump), `GET /api/fm/audit/verify` (chain check, unscoped token), `POST /api/fm/fixity/check` (SHA-256 baseline in the tenant's `_fluxfiles/fixity.json`, unexplained changes audited as `fixity_mismatch`) and `POST /api/fm/audit/purge` (admin-only: requires an unscoped token, since `audit.jsonl` is per-disk not per-tenant) are gated by the `audit-export` module + `allow_audit_export` claim. Every mutating route resolves to a named audit action (CI guard), plus `zip_download`, `presign_*`, `access_denied`; reads only with `audit_reads`.
- **Retention rules** (`retention_rules` claim, `POST /api/fm/retention/run`, gated by the `legal-hold` module): trash/delete files unchanged for N days, `dry_run` by default, legal holds always win, nothing runs on its own (the operator's scheduler calls it). **Legal-hold enforcement** is free/core and license-independent, and since core-v0.2.94 also blocks in-place mutation of a held file (overwrite, presign/chunk/tus onto it, `/content`, `/chmod`, watermark, extract-overwrite, optimize, metadata edits, module writes).
- **SSO bridge is pre-auth, so it can't use the normal 3-layer `ModuleRegistry::require()`** — there's no `Claims` yet to check a per-token claim against. `ModuleRegistry::requireServer($id, $license)` does layers 1+2 only (installed + licensed); layer 3 becomes an explicit `FLUXFILES_SSO_ENABLED` env check in each route (`SsoModule::claim()` returns `''`, per `ModuleInterface`'s contract for claim-less modules). Logins use PKCE (S256). The FluxFiles user id is the IdP `sub` by default (`FLUXFILES_SSO_USER_CLAIM`; `email` only when `email_verified`), and `FLUXFILES_SSO_CLAIMS_MAP` precedence is the map's own order, never the IdP's group order. The real JWT, once minted post-login, is sealed (AES-256-GCM) inside a one-time boot token handed to the standalone UI via a URL **fragment** (`#boot=…`, 60s TTL) rather than a query string — fragments never reach server logs — then a `POST /api/fm/sso/exchange` trades it for the real JWT over a response body, held in JS memory only, never persisted. OIDC only (no SAML).
- **Virus scan is wired fail-closed, and that's load-bearing.** `allow_virus_scan` makes `index.php` (and the Laravel/WP proxies, which build their own `FileManager`) set `FileManager::setVirusScanner()`; the `ModuleRegistry::require` gate runs **inside** the callback so reads still work and only writes needing a scan fail. Scanned: `upload()` (so also `/import-url` and `/tus`), `putContent()`, every `extractZip()` entry — each **before** the bytes are written. Anything that prevents a scan (module absent 501 / licence 402 / claim 403 / engine down 502) **refuses the write**; a malformed verdict counts as infected. `/api/fm/chunk/*` and presigned PUT/POST return `409 virus_unscannable` while the claim is on, because those bytes go browser→S3 and can never be scanned — don't "fix" that by letting the route through. The module scans by **path** (`scanPath`), not bytes, so uploads aren't loaded into memory.
- **Webhooks is shipped and intentionally at-most-once.** `docs/ROADMAP.md`'s DROP table once listed Webhooks as out-of-scope ("needs a persisted outbox + retries"); `COMMERCIAL-STRATEGY.md` §6b (2026-06-28) reversed that — event-driven **is** stateless when the webhook fires on the request that caused the event. `WebhooksModule::dispatch` is post-response, synchronous, best-effort: a dead endpoint loses the event (`error_log` only). Only the *guaranteed-delivery* variant (outbox + retries) stays dropped. Don't "fix" the missing retries by adding a queue.

## Tests & Tooling

- Core PHP tests: `packages/core/tests/{unit,integration}/*.php`, e2e `tests/e2e/test-api.sh` + env-gated `tests/e2e/test-s3-live.php` + self-booting `tests/e2e/*-http.php` (start their own `php -S`, back up/restore `packages/core/.env`, need `curl`). **All `tests/e2e/*-http.php` run in CI** via the `selfboot-e2e` job, which also boots an `atmoz/sftp` container so `test-sftp-http.php` + `test-sftp-live.php` actually execute. A new self-booting test is picked up automatically if it matches `*-http.php`; give it an unused port — taken: 8099, 8101, 8103–8109, 8110–8118 (+8163), 8119, 8121, 8123, 8130–8135, 8151 (or bind an ephemeral port like `test-write-policy-http.php`); `.claude/development.md` has the per-file list. Browser tests: `tests/browser` (Playwright on the standalone `/public/` UI, incl. `media-preview.spec.ts`). Run: `for f in packages/core/tests/unit/*.php packages/core/tests/integration/*.php; do php "$f"; done`.
- **Real-adapter e2e** (debugging the embedded UI through the framework wrappers, vs `tests/browser` which hits the standalone `/public`): `packages/core/tests/apps/` drives the ACTUAL `@fluxfiles/{react,vue}` wrappers, a real Laravel proxy app, and the real WordPress plugin against a live core iframe.
