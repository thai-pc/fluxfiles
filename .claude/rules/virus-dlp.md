**Virus scan is wired fail-closed, and that's load-bearing.** `allow_virus_scan` makes `index.php` (and the Laravel/WP proxies, which build their own `FileManager`) set `FileManager::setVirusScanner()`; the `ModuleRegistry::require` gate runs **inside** the callback so reads still work and only writes needing a scan fail. Scanned: `upload()` (so also `/import-url` and `/tus`), `putContent()`, every `extractZip()` entry — each **before** the bytes are written. Anything that prevents a scan (module absent 501 / licence 402 / claim 403 / engine down 502) **refuses the write**; a malformed verdict counts as infected. `/api/fm/chunk/*` and presigned PUT/POST return `409 virus_unscannable` while the claim is on, because those bytes go browser→S3 and can never be scanned — don't "fix" that by letting the route through. The module scans by **path** (`scanPath`), not bytes, so uploads aren't loaded into memory. Also scanned: same-disk `copy()`, `crossCopy()`, `crossMove()` (stored source streamed to a temp and scanned by `stageScannedCopy`) since the source disk may be unscanned or predate the claim. **The destination is written from that scanned temp file, never from a second read of the source** (TOCTOU: a writer could swap the source mid-scan) — keep it that way. With a scanner wired, cross-disk copy/move skip `_variants/` (regenerable cache), and a same-disk S3 copy downloads instead of server-side CopyObject. Deliberately unscanned (no new object, so don't "fix" one without the others): same-disk `move()`/rename/folder move, trash restore, `removeWatermark()`. The temp file can leak on a fatal/timeout (shared with `writeScopedStream`).
